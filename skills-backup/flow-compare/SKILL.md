# 流程对比技能

## 做什么
给定一个前端功能（源码目录），对比“基线（v1）”与“当前源码”的分析结果，按**流程维度**输出人能看懂的中文变化报告：
流程新增/移除 → 步骤增删改 → 填表单步骤下钻到字段（新增、移除、属性变化、依赖/带出变化）→ 页签、面板、按钮、抽屉、表格变化。

## 前置条件
- 工具所在目录：`/data/pdl/code/wt-d9f4f977ec07`（choerodonTest，命令 `pnpm -s ata`）。
- 分析需要 `LLM_MODE=delegate`（走委派通道，约 3–4 分钟，必须前台跑完，上限 10 分钟）。
- 前端源码：`/data/pdl/repos/pdl-front`。**只读，不得提交、推送**；做实验改源码后必须回退并确认 `git status` 为 0。

## 操作步骤
1. **确认对象**：功能名（`-f`）和功能目录（`-d`，相对源码根）。例：`-f Customer -d packages/key-base-front/src/routes/org/Customer`。
2. **检查基线**：`pnpm -s ata compare -f <功能> --list`。
   - 没有基线：先在**干净源码**上跑 `analyze`，再 `snapshot -l v1`（需用户确认再存）。
   - 基线没有页面结构数据：报告会提示，需用当前代码重存基线（`analyze --no-baseline` 后 `snapshot`）。
3. **分析当前源码**：`pnpm -s ata analyze -f <功能> -p <源码根> -d <功能目录>`。源码与基线一致时直接复用基线，不调模型。
4. **对比**：`pnpm -s ata compare -f artifacts/<slug>/feature.yaml`。
   - 模型总结步骤因缺 DeepSeek 配置会报错退出，**不影响**中文报告，已在它之前写出。
5. **取报告**：`artifacts/<slug>/compare/latest-report.zh.html`（颜色版）和 `latest-report.zh.md`（图标加粗版）；原始数据 `latest-diff.yaml`。
6. **交付**：短结论直接回复；报告较长时发 HTML 附件（颜色版），并附 Markdown 版。

## 报告怎么读
- 颜色（HTML）：绿 = 新增，红 = 移除，橙 = 修改，黄 = 需人工确认；属性变化写成“旧值（红色删除线）→ 新值（绿色加粗）”。
- Markdown 版用图标代替颜色：🟢 新增、🔴 移除、🟡 修改、⚠️ 需确认。
- 报告结构：一句话结论 → 流程总览表 → 有变化的流程（按操作顺序逐步）→ 页面结构汇总 → 需人工确认事项。

## 必须告诉用户的限制
- “关联推断”（保存按钮影响哪些流程、面板被删使哪条流程失效）是按名称匹配出来的，不是源码里的直接证据。
- 整条流程新增/移除可能只是分析波动，不一定是真实变化。
- 抽屉里的字段变化能否挂到“填写抽屉”步骤，取决于模型是否生成了该步骤；挂不上时只出现在“页面结构汇总”。
- 条件渲染（`cond && <字段/>`）和动态表达式只记录表达式原文，不求值。
- 不带基线重新分析时，流程条数可能变化（模型拆分粒度波动），对比前请先确认基线与当前同口径。

## 不做的事
- 不改前端源码并提交；不推送基线（推送需用户指定分支并确认）。
- 不对用例做影响分析（第二期）。
